## 1. Confirm the gating points

- [x] 1.1 Decided: filter out of `get_audio_capture_ports()` entirely (approach 1) - both the Audio Input screen (`zyngui/zynthian_gui_audio_in.py`, `fill_list()`) and `device_cables` (`zynthian_gui_touchkeypad_v5.py:378`, `draw_connections()`) already iterate this list live/fresh on every refresh; neither has any "listed but marked disconnected" state anywhere, so filtering is the only pattern with actual precedent.
- [x] 1.2 Decided: actively disconnect, via the existing pipeline, not new code - `audio_autoconnect()` (zynautoconnect.py:1181-1204) already reconciles `current_routes` against the newly-computed desired sources and disconnects anything no longer wanted, triggered whenever `update_hw_audio_ports()` sets `dirty` (which calls `chain.rebuild_audio_graph()` for every chain). Folding the jack-presence check into that same `dirty` signal (task 2.1) means an already-routed chain gets actively disconnected for free - no `stop_alsa_in`-equivalent needed, since the onboard port is never destroyed (see 2.1's note), only filtered from the list `get_input_pairs()` reads.

## 2. Implement jack-presence polling and the default-routing fix

- [x] 2.1 Added `check_onboard_mic_present()` (amixer -c sofhdadsp cget numid=11, robust True fallback if the card doesn't exist - real hardware/Docker) and a module-level `onboard_mic_present` flag to `zynautoconnect.py`, folded into `update_hw_audio_ports()`'s existing `dirty` accumulation (same ~2s cycle) so a presence change triggers the same existing "rebuild all chains + audio_autoconnect()" tail that USB hotplug changes already use. Note found during implementation: the onboard codec's ports are jackd's own permanent hardware ports here (real jackd bound to `hw:sofhdadsp,0`, confirmed live) - never destroyed by jack-sense state, unlike a USB device's bridged ports, so gating has to happen by filtering the list (2.3), not an alsa_in/alsa_out-style lifecycle.
- [x] 2.2 In `zynthian_chain.py`'s `reset()`, `self.audio_in` now defaults to `[]` when `zynautoconnect.onboard_mic_present` is False, `[1, 2]` unchanged when True.
- [x] 2.3 `get_audio_capture_ports()` now filters `system:capture_1`/`system:capture_2` out when `jack_audio_device == "sofhdadsp" and not onboard_mic_present`, same as the existing `jack_audio_device == "Dummy"` filter just above it.
- [x] 2.4 No new code needed - handled by 2.1+2.3 together (see 1.2's decision).
